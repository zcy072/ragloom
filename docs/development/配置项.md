# 配置项

后端配置全部来自环境变量，由 `backend/services/core/settings.py` 读取，默认值和取值范围只在那里定义。超出范围的整数会被截到边界，无法解析时使用默认值；布尔值只认 `1`、`true`、`yes`、`on`（不区分大小写），其余都算关闭。

Compose 部署时，后端容器通过 `env_file` 读取 `.env` 中的全部变量，没写的变量使用代码默认值。`.env.example` 只列出部署时需要填写或常改的几项。修改 `.env` 后用 `docker compose up -d` 重新创建容器，`docker compose restart` 不会重新读取 `.env`。

新增配置项时，在 `settings.py` 中读取，并在本文对应分组里补一行。`backend/tests/test_deployment_config.py` 会检查本文与 `settings.py` 的变量名一一对应。

## 密钥与账户

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MODEL_API_KEY_ENCRYPTION_KEY` | 无，必填 | SQLite 中模型 API Key 的加密主密钥，至少 32 个字符，每套部署单独生成：`openssl rand -hex 32`。只有数据库而没有该值时，已保存的模型 API Key 无法恢复 |
| `MODEL_API_KEY_PREVIOUS_ENCRYPTION_KEYS` | 空 | 轮换主密钥时临时填写旧密钥，多个用英文逗号分隔。启动后数据库改用新主密钥重新加密，确认服务正常后清空 |
| `SILICONFLOW_API_KEY` | 空 | 嵌入与重排使用的 SiliconFlow Key。“模型管理”里保存了 SiliconFlow 的 Key 时优先用那份 |
| `INITIAL_ADMIN_PASSWORD` | 空 | admin 的初始密码，只在首次建库时生效。留空时随机生成并写入 `storage/data/initial_admin_password.txt`，登录改密后删除该文件 |
| `AUTH_SECRET_KEY` | 空 | 登录令牌的签名密钥。留空时生成随机密钥并保存在应用数据库中；多实例部署时所有实例必须配置相同的值 |
| `AUTH_TOKEN_TTL_SECONDS` | 28800 | 登录令牌有效期（秒），最小 1 |

## 登录与注册限流

计数在进程内存中，重启后清零。次数或窗口设为 0 即关闭该项。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `AUTH_LOGIN_MAX_FAILURES` / `AUTH_LOGIN_WINDOW_SECONDS` | 5 / 900 | 同一用户名在窗口内连续密码错误达到次数后锁定 |
| `AUTH_CLIENT_MAX_FAILURES` / `AUTH_CLIENT_WINDOW_SECONDS` | 20 / 300 | 同一来源地址在窗口内的密码错误总数，拦截用一个密码试很多用户名 |
| `AUTH_REGISTER_MAX_ATTEMPTS` / `AUTH_REGISTER_WINDOW_SECONDS` | 5 / 3600 | 同一来源地址在窗口内的注册提交次数，成功失败都算 |
| `AUTH_TRUST_X_REAL_IP` | 代码 false，Compose true | 是否把 `X-Real-IP` 请求头当作来源地址。Compose 内的 Nginx 会设置该请求头，所以 `docker-compose.yml` 默认开启。后端直接对外暴露、前面没有可信代理时必须关闭，否则请求头可以伪造 |

## 问答

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `CHAT_RETRIEVAL_PLANNING` | false | 让聊天模型通过 function calling 决定本轮是否检索知识库。只在所选模型可靠支持 tools 时开启；普通文本或无效的工具响应会降级为强制检索 |
| `CHAT_QUERY_VARIANT` | false | 在原问题之外再生成一条口语转书面语的补充查询并合并召回，每轮多一次改写模型调用。补充查询失败或丢失编号、数字时被丢弃 |
| `CHAT_AGENTIC_RETRIEVAL` | false | 首轮证据不足时让聊天模型给出新检索词补充检索，最多 2 轮，需要模型支持 tools。评测无收益且延迟变高，见[检索评测](检索评测.md) |
| `CHAT_USER_MAX_CONCURRENT` | 2 | 单个账号同时进行的流式问答数，超限返回 429；0 为不限 |
| `CHAT_USER_PER_MINUTE` | 10 | 单个账号每分钟提问次数，超限返回 429；0 为不限 |
| `WEB_SEARCH_DAILY_LIMIT` | 500 | 联网搜索全站每日次数上限；0 为不限。联网搜索复用“模型管理”中 DeepSeek 的密钥，按成功请求计费 |
| `WEB_SEARCH_USER_PER_MINUTE` | 5 | 联网搜索单个账号每分钟次数上限；0 为不限 |

以上限流计数都在进程内存中，重启后清零。

## 图片分析

适用于独立上传的图片，以及 MinerU 从文档中提取的流程图、示意图等视觉内容，详见[文档处理与索引](文档处理与索引.md)。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `RAG_IMAGE_ANALYSIS` | `auto` | `auto`：视觉模型，失败时改用本地 OCR；`ocr`：只用本地 OCR；`disabled`：跳过图片。其他值按 `auto` 处理 |
| `RAG_VISION_PROVIDER` | `OpenAI` | 视觉模型的提供商，名称须与“模型管理”中的提供商完全一致 |
| `RAG_VISION_MODEL` / `RAG_VISION_BASE_URL` / `RAG_VISION_API_KEY` | 空 | 覆盖“模型管理”中该提供商的模型、接口地址和 Key，通常留空 |
| `RAG_VISION_TIMEOUT_SECONDS` | 60 | 视觉模型请求超时（秒），10~180 |

## 索引并发与任务历史

`INDEX_WORKER_THREADS` 是同时处理的文档数，其余几项限制所有索引任务合计占用某类资源的上限。接口限流较严格时调低对应项。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `INDEX_WORKER_THREADS` | 3 | 并行索引的文档数，1~8；设为 1 即串行 |
| `OCR_MAX_CONCURRENCY` | 1 | 本地 OCR 推理并发，1~4 |
| `MINERU_MAX_CONCURRENCY` | 3 | MinerU 云端解析并发，1~8 |
| `EMBEDDING_MAX_CONCURRENCY` | 2 | 嵌入请求并发，1~8 |
| `VISION_GLOBAL_MAX_CONCURRENCY` | 6 | 视觉模型请求并发，跨文档合计，1~32 |
| `INDEX_JOB_HISTORY_RETENTION_DAYS` | 90 | 终态索引任务（完成、失败、被替代、中断）的保留天数，最小 1 |
| `INDEX_JOB_HISTORY_MAX_PER_KB` | 200 | 每个知识库最多保留的终态任务数，最小 20 |

## 存储路径

Compose 部署时 `STORAGE_DIR` 和 `MINERU_RESULTS_DIR` 由 `docker-compose.yml` 固定，不要在 `.env` 中修改。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `STORAGE_DIR` | 项目目录下的 `storage` | 所有持久数据的根目录 |
| `DATA_DIR` | `$STORAGE_DIR/data` | SQLite 数据库所在目录 |
| `DB_FILE` | `$DATA_DIR/app_data.sqlite3` | 应用数据库文件 |
| `LOG_DIR` | `$STORAGE_DIR/logs` | 日志目录 |
| `MINERU_RESULTS_DIR` | `$STORAGE_DIR/mineru_results` | MinerU 解析结果目录 |

## 部署与构建

这些变量由 `docker-compose.yml` 读取，后端代码不使用。构建变量只在 `docker compose build` 时生效，详见[开发与交付](开发与交付.md)。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TZ` | `Asia/Shanghai` | 容器和日志使用的时区；数据库时间统一保存为带偏移的 UTC |
| `APP_UID` / `APP_GID` | 1000 / 1000 | 后端容器写入 `storage/` 时使用的宿主机 UID/GID。仅在 Linux 出现 `storage/` 权限错误时改成 `id -u`、`id -g` 的输出并重新构建 |
| `DOCKER_LIBRARY_PREFIX` | `docker.m.daocloud.io/library` | Docker Hub 基础镜像前缀，镜像站不可用时改为 `docker.io/library` |
| `PIP_INDEX_URL` | `https://pypi.org/simple` | Python 包索引。构建容器直连官方 PyPI 很慢时改为 `https://pypi.tuna.tsinghua.edu.cn/simple`；锁文件带 hash，内容不一致会构建失败 |
| `NPM_REGISTRY` | `https://registry.npmmirror.com/` | 前端 npm 源 |
| `MILVUS_IMAGE` | `docker.1ms.run/milvusdb/milvus:v2.6.0@sha256:…` | Milvus 镜像，完整默认值见 `docker-compose.yml`。能直连 Docker Hub 时可去掉 `docker.1ms.run/` 前缀。保留 `@sha256` digest，升级时 tag 与 digest 一起改 |
